# Retake v0.0.1: the implementation plan

Status: **planned** (2026-10-26). The contract is written ([README](../../README.md),
[docs/cli.md](../cli.md)) and the [proofs of concept](2026-10-26-proofs-of-concept.md) behind it
are done. This record is the plan for building it, as a series of commits on the
`initial-implementation` branch, the first of which adds the command line.

**The README and docs/cli.md define what Retake does, and every commit conforms to them.** This
plan doesn't restate them: it says in what order they're built, what each step has to prove, how
it's tested, and how Puzz moves over. Where the plan and the contract seem to differ, the contract
wins, and the plan is corrected.

## Puzz, Retake's first user

[Puzz Kids](https://apps.apple.com/us/app/puzz-kids/id6749132459) ([puzz.kids](https://puzz.kids))
is an iPhone and iPad app of puzzle games and read-aloud books for children. Its App Store previews
were made by a pipeline built in its own repository, and Retake is that pipeline extracted into a
tool for any app. Puzz is the first app to use Retake, so switching its previews over to Retake is
v0.0.1's final check.

Retake is generic. Puzz is named here, in the plan for Retake's first version, because that check
is part of the plan; it isn't named in Retake's code, its comments, or its other
documentation, and shouldn't be.

## Goal

v0.0.1 is everything the [README](../../README.md) and [docs/cli.md](../cli.md) describe, working
as they describe it, released. Every command does what its section says, every field of every file
is read and acted on, and anything the docs promise that isn't built by the end is taken out of
them rather than left as a stub. It's done when:

1. **Every documented command and field works**, to the contract, with tests, and with what needs
   a device shown on one.
2. **Puzz's previews are made with it.** Puzz's three videos are recorded and cut by Retake, for
   iPhone and iPad, from scenes, sets and edits in Retake's format, replacing the tooling Puzz grew
   for them (`Scripts/PreviewVideo/`: `take.sh` and its recorder, `edit.sh` and its editor,
   `derive-ipad-edit.py`, and `Scripts/launch-heist.sh`), with none of it left in the path.
3. **v0.0.1 is released**, as the README's Install section says: a signed, notarized `retake` on
   GitHub Releases, installed with `mise`, carrying TheInsideJob and Retake's support library.
4. **The repository shows how to use it**: an example app in `Examples/`, with its own
   `retake.json`, sets, scenes and edits, and an integration test that takes it from install to a
   cut video, as a model for a project of one's own.

## How the work is cut

Each step is one commit, small enough to review on its own and complete on its own terms: it
builds, its tests pass, and what it adds works, even when nothing uses it yet. A step that needs a
device to prove it is tested on one, and what it showed is noted against its check below, in the
same commit. A commit that grows too big to review is split rather than squeezed.

- **The docs are the contract.** A command whose commit hasn't landed yet fails saying so, on the
  branch; none does in v0.0.1. A change to what a command does goes into `docs/cli.md` or the
  README on `main` first, as its own commit, and the branch follows it; the branch carries code and
  tests.
- **Everything added is tested**; see [Testing](#testing).
- **The checks are worked off as the commits land.** Each group of commits below lists what it has
  to prove beyond its unit tests, most of it on a device. A commit ticks the checks in its area,
  noting what each showed, or moves one to [After v0.0.1](#after-v001) when the release doesn't
  need it. By the release, no check is left open.
- **Ported code is reshaped, not copied.** Puzz's recorder and editor, and the spikes, are the
  starting point for much of what follows. Each is moved to Retake's file formats and its anchors,
  rather than carried over with its old shape and adapted later.

**The example app (2).** A small SwiftUI app, a notes app like the README's examples, with
buttons, typing, a sheet that arrives late, a drag and a screen that turns: everything a scene can
drive, and nothing tied to any one app. It replaces the spikes' sample app as what each device
check runs against, and its `retake.json`, sets, scenes and edits grow with the commits that read
and use them, so they're always an example that works. Its Xcode project is checked in, so it
builds with Xcode alone; signing comes from a local, untracked setting naming the developer's
team.

Checks:

- [x] Driven on the iPad (iOS 26.6.2) through The Button Heist 0.7.1's public client, built with
      Xcode 27.2 and the release's TheInsideJob injected: the welcome screen, New Note, typing a
      title and return, waiting for Synced, sharing, dragging a row to reorder, and the two-column
      layout in landscape. Its first layout chose landscape whenever its height was less than its
      width, which the keyboard made true on an iPad in portrait, rebuilding the editor and losing
      the field being typed into; it now leaves the keyboard out.

**Reading the project (3–8).** Swift types for `retake.json`, sets, scenes and edits, read
strictly: a key Retake doesn't know is an error, and every error names the file and the path to the
field (`edits/video1.json: clips[3].from.fraction: 1.4 is outside -1 to 1`), not `DecodingError`'s
coding path. Each field's description, range and default is written once, on its type, since the
schemas (31) and the reference (32) are generated from them. Sets resolve `extends` without cycles;
scenes check their step ids, give their steps a hold from `defaultHold` when they don't give their
own, and add nothing to their set's launch, which is all of it; edits hold anchors and per-device overrides, and still read a time
given in plain seconds. `validate` gets every check a schema can't make that needs no takes; the
ones that need takes come with anchors (24).

**Editing (24–30).** Anchors resolve against a take's step log, the same way for `cut`, `conform`
and `validate`, and so do the elements spotlights and blurs name. The editor is Puzz's
`PreviewEdit`, reshaped around anchors and one edit per video with per-device overrides, and split
across four commits so each is reviewable. Turns are added from proof of concept 4
(`spikes/edit/render-turns.sh` is the stand-in), with the edit's `background` colour around them.
They're only ever real: a preview that shows the device turning records a scene that turns it. A
turn faked in the edit, as a transition between clips, would be added only if a real one proves to
look worse, and Puzz's iPad video 2 is the test of that. `conform` pins an edit to new takes and
turns plain seconds into anchors, which is also how Puzz's edits move over. `status` and `info`
report on what the rest writes, including each movie's metadata. App Store Connect's current preview
requirements for each device type — sizes, frame rates, length, codecs — are looked up before the
export lands, since the canvas and the checks `cut` makes come from them.

## After v0.0.1

Known limits the README states, or tests that wait until a release needs them:

- App group containers and defaults suites (`UserDefaults(suiteName:)`): redirecting a group's
  container to a per-take copy, which its extensions don't see, copying a set's files into one,
  and suites in the in-memory defaults.
- A set's `defaults` with values JSON can't express, such as `Data` and `Date`.
- `devicectl`'s newer device commands as set fields or checks: `simulate statusBar` (rather than
  relying on capture to clean it), `settings appearance` for light and dark, `simulate location`,
  and whether its `capture screen-record` could replace the recorder.

## Testing

Every commit tests what it adds, enough to trust that it works and to catch it breaking later. The
tests are for behaviour that could be wrong, not for code that can't be:

- **What's worth a test.** The contract: what each command does, its errors and exit statuses.
  Reading files: every rule a field has, and the message and path for each way of breaking it.
  The logic Retake owns: anchors and their arithmetic, choosing a device, `extends`, per-device
  overrides, conforming an edit, the editor's timing (where each clip, caption and sound lands on
  the video's clock), and metadata written and read back. And every bug fixed, with a test that
  failed before the fix.
- **What isn't.** Restating a constant, a property returning what it was given, or what a library
  already guarantees, such as ArgumentParser parsing a flag. A test that couldn't fail for a real
  mistake isn't written.
- **Unit tests are fast and need no device.** None takes more than a second, and the suite runs
  under a time limit of seconds, so a test that hangs is found at once. What talks to the outside
  — `devicectl`, `codesign`, The Button Heist, AVFoundation's capture — sits behind a small seam,
  so the logic around it is tested against recorded output: `devicectl`'s JSON captured from real
  devices, a step log from a real take. The editor is tested by rendering short compositions from
  small generated movies and checking frames and times, not by eye.
- **Devices are tested on devices.** What only a device can show is checked on one when it lands,
  and noted against its check in this plan. The example's integration test (34) repeats the
  whole path on a device, and is opt-in: it runs when a device is named for it
  (`RETAKE_DEVICE`), and is skipped otherwise, so `swift test` never needs one. Its parts that
  need no device, `validate` on the example project and `cut` from a small take checked in for
  it, run every time.

## To discuss

Judgement calls and grey areas met while building, none blocking, each kept going with the choice
described, to settle in review. Each names the commit it came up in.

- **Lists in error paths count from 0, steps in anchors from 1** (3). An error's path follows JSON
  tools and editors, so the third step is `steps[2]`, while an anchor's `step` numbers steps from
  1, so the same step is `{ "step": 3 }`. docs/cli.md's example, `scenes/ipad/create-note.json:
  steps[2]: unknown key "tapp"`, reads either way. The alternative is counting paths from 1 to
  match anchors, at the cost of differing from every JSON tool.
- **`null` for an optional key is an error, not the key left out** (3). `"speed": null` fails with
  "expected a number, found null", since no field means anything by `null`, and a strict reading
  that rejects unknown keys should reject a value that says nothing as well. Treating `null` as
  absent would be friendlier to generated files.
- **A pre-release reads its release's schema** (3). `0.0.1-dev` reads files whose `"$schema"`
  names `0.0.1` without a warning, and `init` will write `0.0.1`'s URL, since pre-releases have no
  published schemas of their own.
- **A `"$schema"` that isn't one of Retake's URLs is accepted without a word** (3), on the view
  that a project may point editors at a local copy; only one of Retake's own URLs naming another
  version, or another kind of file, warns.
- **Values may nest 100 deep** (3). The parser stops there with an error rather than recursing
  further: no Retake file nests more than about ten deep, and Swift Testing's threads overflowed at
  500.
- **`init` without a terminal leaves `build` out rather than failing** (4). When the directory's
  Xcode project has several schemes and no one can be asked, `init` still creates the project,
  without `build`, and notes which schemes there were; `install` then needs `--scheme` or `--app`
  until `build` is added. Failing instead would make a script give `--scheme` up front.
- **`init` names a workspace only when xcodebuild couldn't tell** (4): a workspace beside its
  project, as CocoaPods leaves, is written as `"workspace"`; a lone project or workspace isn't
  written at all, since `xcodebuild` finds it. It looks only in the current directory, not in
  folders below it.
- **Notes and warnings go to standard error, prefixed `note:` and `warning:`** (4), so that output
  meant for a pipe, or `--json`, stays clean; errors keep their `✖`.
- **How a set lies over the set it extends** (5). The README says only that `extends` "builds on
  another set". As built: `files`, `defaults` and `environment` merge by key, the extending set's
  value replacing the base's; `aspect` merges by device type; `state` is the nearest set's that
  gives one, else `clean`; and `arguments` add up, the base's first, so a set can't take back an
  argument its base passes. A default whose value is an object replaces the base's whole, rather
  than merging into it. The README could say this in a sentence.
- **A set can't set `DYLD_*`, `INSIDEJOB_*` or `RETAKE_*` in its `environment`** (5), since Retake
  launches the app with its own; a set naming one fails. It could instead be allowed with a
  warning, for someone deliberately overriding Retake's choice.
- **A `files` entry's trailing `/` must match on both sides** (5): a destination ending in `/` is
  a folder, copied from a source folder ending in `/`, and a mismatch is an error rather than a
  guess. Destinations can't start with `/` or contain `..`, and sources can't leave the project.
- **`occurrence` counts from 1** (6), like an anchor's step numbers, though The Button Heist's own
  ordinal, which it becomes, counts from 0. It's the field a person writes when two buttons share a
  label, so it reads as "the second Delete".
- **`inspect` is given as `true` or `{}`** (6), since it takes no options yet; `{}` leaves room for
  some, such as limiting it to a part of the screen.
- **A scene's `set` defaults to `defaultSet`** (6), so the README's "a scene names its set" became
  "names it, or the project's `defaultSet`"; `validate` reports a scene with neither (8).
- **Steps can't be held on the setup list with ids** (6): setup isn't recorded, so an id there would
  name a moment no take has. Holds are allowed in setup, to let the app settle before recording.
- **Edit fields the README describes without naming** (7). The clip's longer sound cross-fade is
  `audioCrossfade`, as in Puzz's edits, beside `takeAudio`; it can't be shorter than `crossfade`.
  A still is `{ "take", "at" }`, a frame of another take, and stills pop in one after another
  from the clip's start, as Puzz's do, with no timing of their own yet. A spotlight's `padding` is
  8 points and its ring white unless given; a blur's `radius` is 20.
- **An anchor's `edge` is `"start"` or `"end"`** (7): the edge of the step an `offset` or
  `fraction` counts from, overriding the README's default of forward from the end and back from
  the start. The README's "`edge` counts from the step's other edge instead" reads as a flag; a
  named edge says the same thing without a reader having to work out which edge is "other".
- **Overrides can't give `devices`, `takes` or `intent`** (7), which are per edit, or already per
  device type; any other field, at the top or inside a clip, caption or any object, can be. An
  override inside an override, such as `"ipad": { "iphone": … }`, is an error.
- **Volumes have no upper limit** (7): `volume` and `takeAudioVolume` must be 0 or more, so a quiet
  effect can be raised above its file's level; 1 is the file as it is.
- **`validate` checks anchors against scenes without takes** (8). docs/cli.md lists anchors
  resolving among the checks that need takes; an anchor's step id existing in its scene, or its
  number being in range, needs only the scene, so `--offline` checks that too, as the README's
  "an anchor's step id existing in its scene" suggests. Resolving the moments themselves still
  needs takes (24).
- **`validate` without `--offline` notes that takes aren't checked yet** (8): until anchors
  resolve against takes (24), it runs the offline checks and says so, rather than failing.
- **Validating named files reports only their own problems** (8). A scene named on its own is
  checked against its set, but a problem inside that set isn't reported unless the set is named
  too.
- **Retake waits out macOS releasing a device's screen** (10). A process asking for a device's
  screen within about 8 seconds of another releasing it is never offered it, so Retake records
  when it releases the screens and waits out the rest before asking again, up to 8 seconds; see
  the Devices checks. The wait isn't announced, since it's short; a note could say why a command
  paused.
- **`devices` lists connected devices only** (10): an unavailable or disconnected device isn't
  listed, though an alias for one is, marked not connected. A device on the network is listed,
  saying it can't be recorded.
- **A build from a clone learns its clone's path and commit from the framework's build** (11).
  SwiftPM's manifest can't run git or write files, so `Package.swift` only marks a build from a
  clone (`RETAKE_BUTTONHEIST_CLONE`), and `retake version` reads the path and commit
  `scripts/fetch-insidejob.sh` recorded when it built the clone's framework. Building Retake from
  a clone without running the script shows the clone as unknown. A build-tool plugin could stamp
  them into the binary instead.
- **A local Retake finds TheInsideJob in `~/Library/Caches/retake/insidejob/`** (11), which
  `scripts/fetch-insidejob.sh` fills, rather than downloading it on first use: the README's
  building-from-source steps run the script, and a command that needs the framework and finds
  none says to. Downloading on first use would save a step.
- **A set's defaults reach the app as JSON in the launch environment** (12), `RETAKE_DEFAULTS`,
  rather than a file staged in the container: they're JSON values already, and copying a file to
  the device costs a second a launch. A set with a very large `defaults` might need the file.
- **The take's staged files are consumed once copied** (12): the support library deletes
  `tmp/RetakeSet/` after laying it out, since nothing on the Mac can delete files in the container,
  and a take whose set has no files would otherwise get the last take's.
- **`clean` keeps launch arguments and the global domain** (12): the in-memory defaults still read
  `-key value` arguments, as a set's `arguments` may give, and global settings such as
  `AppleLanguages`, which the spike's store dropped; only the app's own domain starts empty.
- **The launch report is a file copied back** (13), rather than something read through The Button
  Heist: a hidden accessibility element wasn't visible to it (proof of concept 4), and its status
  carries nothing of Retake's. The copy costs about a second a launch, once a take.
- **An unsigned app gets the minimal development entitlements** (14): given `--identity` and
  `--profile`, `embed` signs an app built with signing off with the profile's app ID for its bundle
  ID, its team, `get-task-allow`, and its own keychain group, as the spikes did, not every
  entitlement the profile allows. An app that needs capabilities should be built signed, for
  `embed` to keep its own.
- **`embed` names the identity it used by its certificate's SHA-1** (14), which is what it reads
  from the app's signature, and what `--json` reports.
- **`install` builds for the device by its id** (16), `-destination id=<UDID>`, rather than for any
  iOS device, so Xcode's signing includes the device, and a build that can't be is caught before
  embedding. The embedded copy goes in `RetakeOutput/build/installed/`, replaced each time, which
  is where "Finding the app" reads the bundle ID from.
- **Recognising an unregistered device is by `xcodebuild`'s message text** (16), which
  `isUnregisteredDevice` matches on phrases such as "doesn't include the currently selected
  device"; the phrases are from Xcode's known messages, not yet seen from a real unregistered
  device here.
- **Each staged file is its own `devicectl` copy** (17), about a second each, so a set with many
  files launches slowly. Copying a folder is one copy; a set could be staged as one archive the
  support library unpacks, at the cost of another contract change.
- **A take's launch stays attached to the app's console** (17), `devicectl … launch --console`,
  logged to `RetakeOutput/logs/<take>.log`: the attached launch holds the device connection for the
  take and keeps the app's output for when a launch fails, whose last lines the error quotes.
- **The Button Heist's port and token are new for each launch** (17), a random port from 20000 to
  60000 and a random token, so a stale app from an earlier take can't be driven by mistake. A port
  already taken on the device fails the launch check rather than being retried.
- **`clean --on-device` waits up to 6 seconds for iOS to reopen the app**, then closes it (17).
  Without the wait, the app closed straight after the cleanup launch is opened again by iOS and
  left running.
- **An `orientation` step ends when the screen's elements have moved and then held still** (18).
  The README says the step "ends when the app has turned", so the next step's points land on the
  turned layout. `devicectl device orientation set` returns in about 0.2 s, before the app has
  relaid out; The Button Heist's `WaitFor(.screenChanged)` doesn't fire for a rotation (proof of
  concept 4); and neither its public client nor `devicectl` gives the screen's size (asks record,
  10). So Retake reads the screen every 0.1 s until the elements' frames differ from before the turn
  and are the same twice running, and fails after 5 s, asking whether the app supports that
  orientation. A turn to the way the device already faces doesn't wait. It could be fooled by a
  screen whose elements don't move when it turns (a single full-screen element, say), which would
  end the step at the 5 s timeout, failed. The alternative without The Button Heist is the support
  library reporting its window's size, which needs a contract change and a file copy mid-take.
- **Drags at other than 0.5 s go through The Button Heist's tooling SPI** (18). 0.7.1 refuses a
  drag with a `duration` inside a plan, the public client's only way to send it ("drag duration …
  is not a durable heist action"); only the tooling SPI's direct commands take one. The contract
  keeps `duration`, and real scenes need it (one app's drags are 0.25 s and 0.8 s), so a drag at
  exactly 0.5 s goes in a plan, and any other is sent with `@_spi(ButtonHeistTooling)`'s
  `admit`/`execute`, confined to `ButtonHeistDriver.perform`. Decided with the project's owner on
  2026-10-27: use the SPI for now, and record what The Button Heist would have to make public to
  drop it (asks record, 8–10). The other choices were dropping `duration` from the contract, or
  playing every drag at 0.5 s with a warning until upstream changes.
- **Client errors are classified from `FenceError`'s public cases** (18). The Button Heist's own
  mapping from an error to its failure code is internal or SPI (asks record, 9), so
  `ButtonHeistDriver.classify` reads `.diagnostic`'s code, and maps `.authFailed`, `.notConnected`,
  `.actionTimeout` and `.sessionLocked` itself. A mismatch is 3 with "embed it again"; a refused
  token is 3; an unreachable server is retried for 10 s, then 3; a connection lost during a step
  is 3; anything else in a step is 1. A new error case in a later release would fall through to 1
  with its description.
- **A launch whose app is never reached is tried once more** (18). The README promises "a launch
  that doesn't take is tried again", and proof of concept 3 saw a first connection fail once and
  then work. Connecting is retried for 10 s; if the app still can't be reached before any step has
  played, the app is launched again, once, with a note. A failure after the first step has played
  isn't retried, since the app's state has moved on.
- **`rehearse` keeps the app's console in a temporary folder** (18), not `RetakeOutput/logs/`,
  since docs/cli.md says rehearsing "writes nothing". The folder is left for the system to clear;
  the error for a launch that fails still quotes the console's last lines.
- **`--from` skips the holds of the steps before it, not the setup's** (18). docs/cli.md says the
  steps before `--from` play "without their holds"; setup steps aren't numbered among the steps,
  and their holds let the app settle before the first step, so they keep them.
- **The cleanup launch runs after a failed rehearsal too** (18), so a failed step leaves no take's
  copy of the app's data on the device. If the cleanup itself then fails, the step's failure is
  what's reported, with a warning to run `retake clean --on-device`. A `live` set has no take copy,
  so it gets no cleanup launch, as `record`'s "when any take was clean or cloned" says.
- **A `waitFor` that runs out is reported in Retake's words** (18): `"Done" was still on screen
  after 4 s.` The Button Heist's own text for it names its predicate
  (`elementsChanged(exists(target(predicate(value="Title"))))`), which says less. Other failures
  pass The Button Heist's message through as it is, which for a missing element is several lines
  listing what was on screen, useful for fixing the step.
- **A `waitFor` over 60 seconds fails only when it plays** (18). The Button Heist refuses a wait
  longer than its maximum, 60 s unless `BUTTONHEIST_MAX_WAIT_TIMEOUT` raises it, but scenes accept
  any positive `timeout`, so a 600 s wait reads and validates, then fails at its step. `validate`
  or the scene reader could check it against the maximum, or the schema give it a maximum of 60.
- **A step's run is given its longest wait plus 60 seconds** (18) as The Button Heist's timeout
  for the plan, so the wait's own timeout is what ends it, not the plan's.
- **`rehearse` prints each step once it has played, with its wall time** (18), nothing while it
  runs: a 10 s `waitFor` is silent until it's done. Printing a step as it starts would show what's
  being waited on, at the cost of two lines a step, or a line rewritten in place.
- **The device's orientation isn't restored after a rehearsal** (18). It's left however the
  scene's last step left it. The next launch turns it to its scene's `orientation` anyway, so a
  take never starts turned; restoring it would need its orientation read before launch, which
  `devicectl device orientation` can do.
- **The example's `reorder` scene is iPad only** (18). It drags a row by its iPad screen points
  and turns the iPad, and there's no iPhone here to read the iPhone's points from, so
  `scenes/iphone/` has no `reorder` yet. An edit that cut it couldn't name both device types until
  it has one. `SceneFileTests` now checks that each type has at least `create-note` and
  `first-launch`, rather than exactly those.
